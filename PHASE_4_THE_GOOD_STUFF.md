# 9. PROJECTS VS ASSETS

This distinction is mandatory.

An asset is not automatically a project.

Correct:

```text
STAY ORIGINAL
├── Full video
├── Poster
├── Preview
├── Supporting images
└── BTS
```

Incorrect:

```text
IMG_4818 = Project
IMG_4814 = Project
IMG_4810 = Project
```

Files become project assets only after a reliable project association exists.

---

# 10. PROJECT READINESS

Classify projects as:

## READY

Enough verified material exists for a strong homepage treatment.

## PARTIAL

Some strong material exists, but important supporting media is missing.

## NOT READY

There is not enough verified media to represent the project properly.

## UNKNOWN

The project/asset relationship cannot yet be established confidently.

The homepage should prioritize READY projects, then selected PARTIAL projects where the presentation remains strong.

# 24. MEDIA PERFORMANCE

Project cards can become expensive quickly.

Do NOT:

- preload every full video
- autoplay every preview
- download full-resolution project footage for cards
- create unnecessary duplicate video instances

```text

↓

↓
full video on project page
```

# 32. QUESTIONS TO ASK THE OWNER

Ask when repository evidence is insufficient to make a safe project/content decision.

Examples:

- Multiple assets could belong to different projects.
- Multiple video versions appear approved.
- Client identity cannot be established.
- Project category cannot be established.
- A critical visual asset is missing.
- A missing asset materially changes the layout decision.
- Brand approval is required.

Do NOT ask questions that inspection can answer.

When asking:

```text
QUESTION:
...

WHY IT MATTERS:
...

WHAT I FOUND:
...

RECOMMENDATION:
...
```

Group questions together and continue all non-blocked work.
